# Review Once Signed Grant — Phase PR-B

> **Security prerequisite:** The signed Human approval event MUST originate from a trusted Host/Broker outside the Agent's writable filesystem. This PR provides deterministic verification and state gating; it **does not implement a trusted Host approval UI or background Runner**. Do not enable fully autonomous execution until the Host provides an actual trusted approval channel.

## Host approval contract

The Human sees the complete `packet.json` generated by `review-once-packet.py`, then explicitly approves. The Host (not Agent code) issues a JSON event with **exact** fields:

```json
{
  "schema_version": 1,
  "decision": "approve_review_once",
  "actor": "human",
  "grant_id": "c2bb6f98-c20d-4e3e-9c38-c75a0d360901",
  "packet_sha256": "<actual digest>",
  "slug": "<task slug>",
  "repository": {"full_name": "<owner/repo>", "branch": "<branch>", "base_commit": "<40-char Git SHA>"},
  "issued_at": "<offset-aware ISO timestamp>",
  "expires_at": "<issued_at plus <=4 hours>"
}
```

The Host signs **canonical JSON UTF-8** (sort keys, compact separators, ensure_ascii=false) with a private key **never exposed to Agents or repository workspace**. The verifier uses OpenSSL SHA256 signature verification with a Host-managed public key at the absolute path in `CREW_REVIEW_ONCE_TRUSTED_PUBLIC_KEY`; it MUST be outside the project directory. If missing or invalid, fail closed.

**Important:** An untrusted Agent controlling environment variables, the public-key path or the user's signing mechanism could still forge a self-signed event. Path checks alone are NOT a security boundary. A production Host must pin the verifier trust root and provide a protected signing/approval channel; until then this is an integration-ready contract, **not an unconditional authorization mechanism**.

## State transitions (crew-state.py is the only writer)

```bash
python3 crew-state.py grant --slug {slug} --action issue \
  --packet packet.json --approval-event approval.json --signature approval.sig
python3 crew-state.py set --slug {slug} --step spec --status done
python3 crew-state.py grant --slug {slug} --action approve-requirement
python3 crew-state.py set --slug {slug} --step db --status skipped --reason DB_REQUIRED=false
python3 crew-state.py set --slug {slug} --step arch --status done
python3 crew-state.py grant --slug {slug} --action approve-architecture
python3 crew-state.py grant --slug {slug} --action check
# After the later Runner reaches build done:
python3 crew-state.py grant --slug {slug} --action consume
# On request:
python3 crew-state.py grant --slug {slug} --action revoke
```

- `issue`: verifies signed event, matching packet SHA, slug, task branch and four-hour wall-clock bound. Requires existing Feature state; will not extend an active grant.
- `approve-requirement`: requires `spec=done` and exact AC/Goal/Spec decision match against approved proposal. Records `by=delegated-review-once`, **never pretends `by=human`**.
- `approve-architecture`: requires `requirement` pass, DB done/skipped, `arch=done`, and approved Spec/Arch/DB decision / SQL match. Existing `TRANSITION_GATES` remain unchanged.
- While active, a direct `gate --by human --status approved` or `waived` for requirement/architecture is BLOCKED.
- `grant check` validates signature, expiry, trust-root fingerprint, task branch and the approved stage snapshots. No side effects.
- `grant revoke` disables autonomous grant. It does not erase earlier valid approvals; manual continuation is a separate operation.
- `grant consume` requires `build=done`; it is not `uat=approved`. Human UAT is never granted automatically.
- Existing Interactive/Legacy/Bug paths without active Review Once remain unchanged.
